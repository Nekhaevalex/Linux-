## 🧠 0. Теория: как устроена macOS (Darwin и XNU)

> Команды забываются, а понимание остаётся. Этот раздел объясняет **почему** в macOS всё работает так, как работает, и чем она отличается от Linux, — после него остальная шпаргалка читается в разы легче.

### 0.1. Ядро XNU, Darwin, Aqua и оболочка

macOS — это сертифицированная система **UNIX 03**, построенная на открытой подсистеме **Darwin** с проприетарными фреймворками Apple поверх неё:

```
┌───────────────────────────────────────────────────────────┐
│  Пользователь                                             │
├───────────────────────────────────────────────────────────┤
│  Оболочка (zsh, bash) / Графика Aqua (Finder, WindowServer)│  ← ты вводишь команды / кликаешь
├───────────────────────────────────────────────────────────┤
│  Фреймворки (Cocoa, SwiftUI, CoreFoundation, Security)    │  ← GUI-приложения (.app)
├───────────────────────────────────────────────────────────┤
│  Darwin Userland: BSD-утилиты и libSystem (libc/libm)     │  ← ls, cp, grep, launchd…
├────────── системные вызовы BSD + ловушки Mach (traps) ────┤  ← open(), fork(), mach_msg()
│  Гибридное ядро XNU (kernel space):                       │
│   ├── Mach (планировщик, виртуальная память, IPC-порты)   │
│   ├── BSD (процессы, POSIX API, права, VFS, стек сети)    │
│   └── I/O Kit (драйверы устройств на C++, управление питанием)│
├───────────────────────────────────────────────────────────┤
│  Железо: Apple Silicon (M1–M4: CPU/GPU/ANE) или Intel     │
└───────────────────────────────────────────────────────────┘
```

| Термин | Что это |
|---|---|
| **XNU** («X is Not Unix») | Гибридное ядро macOS и iOS. Сочетает микроядро **Mach**, слой **BSD** (на базе FreeBSD) и объектно-ориентированную подсистему драйверов **I/O Kit**. Версия: `uname -r` |
| **Darwin** | Открытая UNIX-основа macOS (ядро XNU + BSD-утилиты + демон `launchd`) без графического интерфейса Aqua |
| **Aqua / WindowServer** | Графическая среда macOS. За отрисовку всех окон отвечает процесс `WindowServer` |
| **Терминал** | Программа для текстового ввода: стандартный `Terminal.app`, либо популярные `iTerm2`, `Ghostty`, `Alacritty`, `Warp` |
| **Оболочка (shell)** | Интерпретатор команд внутри терминала. Начиная с macOS Catalina, оболочка по умолчанию — **Zsh** (`/bin/zsh`) |

### 0.2. Анатомия команды и главное отличие от Linux (BSD vs GNU)

```
ls  -l -a  -G           /etc /var
──  ─────  ──           ─────────
│     │    └── цветной вывод в BSD ls (вместо --color=auto в Linux)
│     └── короткие опции (можно слить: -laG)
└── команда (программа, встроенная команда или алиас)
```

- **BSD против GNU:** базовые утилиты в macOS (`ls`, `cp`, `mv`, `sed`, `find`, `date`, `stat`, `du`, `df`, `ps`) унаследованы от **FreeBSD**, а не из GNU coreutils (как в Linux). Поэтому у многих стандартных команд:
  - нет ключа `--help` (читай `man команда`);
  - опции должны идти **строго до** аргументов (например, в BSD `ls /tmp -la` выдаст ошибку или поищет файл `-la`, правильно: `ls -la /tmp`);
  - некоторые ключи отличаются (например, `sed -i ''`, `du -d 1`, `stat -f`).
- 💡 Если нужны именно GNU-версии утилит: `brew install coreutils findutils gnu-sed gawk grep` — они установятся с префиксом `g` (`gls`, `gfind`, `gsed`, `gawk`, `ggrep`).
- **Регистр в именах файлов:** по умолчанию файловая система APFS в macOS **нечувствительна к регистру, но сохраняет его** (*Case-insensitive, Case-preserving*). Это значит, что `File.txt` и `file.txt` — это **один и тот же файл** (если том специально не отформатирован как *APFS Case-sensitive*). При этом в самой оболочке и командах регистр букв важен (`ls -s` и `ls -S` — разные ключи).
- Пробелы в именах экранируй: `"My Documents"` или `My\ Documents`.

### 0.3. «Всё есть файл», бандлы `.app`, расширенные атрибуты (`xattr`) и флаги

В macOS файлами представлены документы, папки, диски (`/dev/disk0`, `/dev/rdisk0`), терминалы (`/dev/ttys000`), «чёрная дыра» `/dev/null`.

> ⚠️ **Важное отличие от Linux:** в macOS **нет виртуальных файловых систем `/proc` и `/sys`**! Информацию о процессах, памяти и железе ядро XNU отдаёт через системные вызовы Mach/BSD и утилиты `sysctl`, `ioreg`, `system_profiler`, `top`, `vm_stat` и `lsof`.

| Символ в `ls -l` | Тип | Пример |
|:---:|---|---|
| `-` | Обычный файл | `/etc/hosts` |
| `d` | Каталог (в том числе `.app`!) | `/Users`, `/Applications/Safari.app` |
| `l` | Символическая ссылка | `/etc → private/etc` |
| `c` | Символьное устройство | `/dev/null`, `/dev/rdisk0` (сырой быстрый доступ к диску) |
| `b` | Блочное устройство | `/dev/disk0` |
| `s` | Сокет | `/var/run/syslog` |
| `p` | Именованный канал (FIFO) | создаётся `mkfifo` |

**Специфика файлов в macOS:**
- **Application Bundles (`.app`, `.framework`, `.kext`):** любая программа в `/Applications` (например, `Safari.app`) для Finder выглядит как один значок, но для терминала — это **обычная папка** с фиксированной структурой внутри (`Contents/Info.plist`, `Contents/MacOS/бинарник`, `Contents/Resources/`).
- **Расширенные атрибуты (`xattr`):** к любому файлу macOS может прикреплять метаданные (теги Finder, откуда скачан файл, флаг карантина Gatekeeper `com.apple.quarantine`). Если у файла есть `xattr`, в выводе `ls -l` после прав появляется символ `@` (`-rw-r--r--@`).
- **Флаги файлов (`chflags`):** дополнительные системные и пользовательские атрибуты BSD (`hidden` — скрыть в Finder, `uchg` — защитить от изменений даже владельцем).
- **Служебные скрытые файлы:** `.DS_Store` (хранит настройки вида папки и позиции иконок в Finder) и `._имя` (файлы AppleDouble, которые macOS создаёт на флешках с FAT/exFAT для хранения `xattr`).

### 0.4. Inode, ссылки, клоны APFS и Firmlinks

Имя файла указывает на **inode** — структуру с метаданными (владелец, права, размер, даты, блоки данных). Номер inode: `ls -i`. В macOS, помимо обычных жёстких и символических ссылок, есть ещё три важных механизма:

```
имя "report.txt" ──┐
                   ├──▶ inode #1234 ──▶ блоки данных на диске
hardlink "copy" ───┘
symlink "link"  ──▶ "report.txt"          (хранит текстовый путь)
APFS clone      ──▶ inode #5678 ──▶ те же блоки данных (Copy-on-Write!)
```

| Механизм | Как создать | Особенности |
|---|---|---|
| **Жёсткая ссылка** | `ln file hard` | Указывает на тот же inode. Не работает между разными томами и на папки |
| **Символическая ссылка** | `ln -s target link` | Хранит путь. Работает между томами и на папки. Если удалить цель — ссылка «битая» |
| **Клон APFS (CoW)** | `cp -c file clone` | 💡 Фишка APFS: создаёт **независимую копию** файла мгновенно и без занятия места на диске! Новые блоки выделяются только при изменении одного из файлов |
| **Алиас Finder (Alias)** | В Finder (`Cmd+Opt+Drag`) | Хранит и путь, и уникальный ID файла — не ломается даже если целевой файл **переместить или переименовать** на том же томе |
| **Firmlink** | Системный (`/usr/share/firmlinks`) | Двунаправленный «мост» между неизменяемым системным томом `/` и томом данных `/System/Volumes/Data` (например, `/Users`, `/Applications`, `/Library`) |

### 0.5. Пользователи, root, Open Directory и права

- Каждый пользователь имеет **UID**, группа — **GID**.
- В macOS обычные пользователи получают UID начиная с **`501`** (`501`, `502`…), а их основная группа — **`staff`** (GID `20`).
- Системные службы работают от служебных аккаунтов, имена которых начинаются с подчёркивания (`_www`, `_postgres`, `_spotlight`, `_windowserver`) с UID меньше `500`.
- **root** (UID `0`, группа `wheel` с GID `0`) по умолчанию отключён для прямого входа по паролю. Администраторы (члены группы `admin`, GID `80`) выполняют привилегированные команды через `sudo`.
- ⚠️ В отличие от Linux, в macOS учётные записи хранятся **не в `/etc/passwd`**, а в службе каталогов **Open Directory** (`/var/db/dslocal/nodes/Default/`, управляется демоном `opendirectoryd` и командами `dscl`, `sysadminctl`). Файл `/etc/passwd` используется только в однопользовательском режиме!
- Для каталога права `rwx` значат то же, что и в любом UNIX:

| Право | Для файла | Для каталога |
|:---:|---|---|
| `r` | Читать содержимое | Видеть список файлов (`ls`) |
| `w` | Изменять содержимое | Создавать, удалять, переименовывать файлы внутри |
| `x` | Запускать как программу | Входить (`cd`) и обращаться к файлам внутри |

### 0.6. Процессы, Mach-задачи и `launchd`

В ядре XNU каждый процесс BSD (`proc`) неразрывно связан с **задачей Mach (`task`)**, которая владеет виртуальной памятью и потоками выполнения (`Mach threads`), а процессы общаются друг с другом через **порты Mach (`Mach ports`)** и высокоуровневый механизм **XPC**.

Прародитель всех процессов с **PID 1** — демон **`launchd`** (вместо `systemd` в Linux). Он управляет как системными демонами (`LaunchDaemons`), так и пользовательскими агентами (`LaunchAgents`) и GUI-приложениями.

| Состояние (`ps` STAT) | Значение в macOS |
|:---:|---|
| `R` | Выполняется или в очереди на выполнение |
| `S` | Спит меньше 20 секунд (ожидает события) |
| `I` | Простаивает (Idle — спит больше 20 секунд) |
| `U` | **Непрерываемый сон** (Uninterruptible wait — ждёт диск/ядро, аналог `D` в Linux; `kill -9` не поможет) |
| `T` | Остановлен (`Ctrl+Z` или отладчиком `lldb`) |
| `Z` | Зомби — завершился, но родитель не вызвал `wait()` |

**Энергоэффективность и QoS (Quality of Service):** на чипах Apple Silicon есть производительные (**P-cores**) и энергоэффективные (**E-cores**) ядра. macOS назначает потокам класс QoS (`User Interactive`, `User Initiated`, `Utility`, `Background`) — фоновые задачи с классом `Background` планировщик автоматически отправляет только на E-ядра, чтобы Mac не грелся и не тратил батарею.

### 0.7. Потоки, пайпы, коды возврата и буфер обмена

У каждого процесса три стандартных потока:

```
              ┌──────────┐ ──▶ 1 stdout (результат)
  0 stdin ──▶ │ команда  │
              └──────────┘ ──▶ 2 stderr (ошибки)
```

Пайп `|` соединяет `stdout` одной программы со `stdin` другой. А в macOS в любой конвейер можно включить **системный буфер обмена** (`Cmd+C` / `Cmd+V`) с помощью команд `pbcopy` и `pbpaste`:

```bash
cat ~/.ssh/id_ed25519.pub | pbcopy    # скопировать ключ в буфер обмена Mac
pbpaste | sort -u > clean_list.txt    # вставить текст из буфера, отсортировать и сохранить
```

Каждая команда возвращает **код выхода** (`echo $?`): `0` — успех, не-ноль — ошибка (`1` — общая ошибка, `126` — нет прав на запуск, `127` — команда не найдена, `130` — прервано `Ctrl+C`, `137` — убит `SIGKILL`).

### 0.8. Как оболочка (Zsh / Bash) находит и запускает команду

По умолчанию в macOS используется **Zsh** (`/bin/zsh`, версия 5.9+). Системный `/bin/bash` в macOS заморожен на старой версии **3.2** (2007 года) из-за смены лицензии GNU Bash на GPLv3. Если тебе нужен современный Bash 5.x (с ассоциативными массивами `declare -A`, `mapfile` и т.д.), установи его через Homebrew: `brew install bash` (он появится в `/opt/homebrew/bin/bash`).

Когда ты вводишь команду, оболочка проверяет по порядку: **алиас → функция → встроенная команда (builtin) → файл в каталогах из `$PATH`**. Посмотреть: `type -a ls` или `which -a python3`.

```bash
echo $PATH
# На Apple Silicon: /opt/homebrew/bin:/opt/homebrew/sbin:/usr/local/bin:/System/Cryptexes/App/usr/bin:/usr/bin:/bin:/usr/sbin:/sbin
./script.sh                             # текущая папка НЕ входит в PATH — нужен ./
export PATH="$HOME/.local/bin:$PATH"    # добавить свою папку (в ~/.zshrc)
```

В macOS системный `PATH` собирается утилитой `/usr/libexec/path_helper` из файла `/etc/paths` и всех файлов внутри папки `/etc/paths.d/`.

**Файлы настройки Zsh в macOS (в порядке чтения):**
1. `~/.zshenv` — читается **всегда** (даже в неинтерактивных скриптах).
2. `~/.zprofile` — читается для **login shell** (в macOS `Terminal.app` и `iTerm2` каждое новое окно терминала по умолчанию запускается именно как *login shell*! Сюда Homebrew добавляет `eval "$(/opt/homebrew/bin/brew shellenv)"`).
3. `~/.zshrc` — читается для каждой **интерактивной** оболочки (лучшее место для алиасов, функций, настройки промпта и автодополнения).

### 0.9. Кавычки, glob и регулярные выражения

| Запись | Что происходит | Пример → результат |
|---|---|---|
| `'...'` | Всё буквально, ничего не раскрывается | `echo '$HOME'` → `$HOME` |
| `"..."` | Раскрываются `$VAR` и `$(...)`, но не `*` и пробелы | `echo "$HOME"` → `/Users/alex` |
| без кавычек | Раскрывается всё | опасно для имён с пробелами и URL со знаком `?` в Zsh |
| `\` | Экранирует один символ | `echo \$HOME` → `$HOME` |

> 💡 **Особенность Zsh:** если в строке есть символы маски (`*`, `?`, `[...]`) и подходящих файлов нет, Zsh по умолчанию **не запускает команду** и пишет `zsh: no matches found`. Поэтому URL с параметрами всегда бери в кавычки: `curl "https://example.com/api?id=1&sort=asc"`.

| Смысл | Glob (оболочка) | Regex (`grep -E`, `sed -E`) |
|---|:---:|:---:|
| Любая строка | `*` | `.*` |
| Любая вложенность папок (Zsh / globstar) | `**/*` | — |
| Один любой символ | `?` | `.` |
| Один из набора | `[abc]` | `[abc]` |
| Начало / конец строки | — | `^` / `$` |
| Повтор 1+ раз | — | `+` |
| Цифра | `[0-9]` | `[0-9]` или `\d` |

### 0.10. Память (Unified Memory), сжатие и нагрузка

На Mac с чипами Apple Silicon используется **Unified Memory Architecture (UMA)** — CPU, GPU и Neural Engine (ANE) работают с общим пулом сверхбыстрой оперативной памяти без копирования данных между RAM и видеопамятью.

В macOS нет команды `free`, вместо неё используются `memory_pressure`, `vm_stat` и `top`:

| Категория памяти в macOS | Что это значит |
|---|---|
| **App Memory (Active / Anonymous)** | Память, занятая запущенными программами и их данными |
| **Wired Memory** | Системная память ядра и драйверов (плюс буферы GPU), которую **нельзя** сжать или выгрузить в swap |
| **Compressed** | 💡 Фишка macOS: прежде чем сбрасывать неактивные страницы на SSD в swap, ядро сжимает их прямо в RAM (алгоритм WKdm / LZ4) в 2–4 раза |
| **Cached Files (File-backed)** | Кэш диска в памяти — мгновенно освобождается для программ по первому требованию |
| **Swap Used** | Сколько выгружено на SSD (`/System/Volumes/VM/swapfile*`). В macOS размер swap динамический — система сама создаёт и удаляет файлы swap по мере надобности |

- **На что смотреть:** не на «свободные гигабайты» (macOS старается использовать всю память под кэш), а на **Memory Pressure** (`memory_pressure`): пока уровень зелёный (`System-wide memory free percentage` > 30–40%) — памяти хватает.
- **Load average** (`uptime`) — среднее число потоков, которые выполняются или ждут CPU/диск, за 1, 5 и 15 минут. Сравнивай с общим числом ядер (`sysctl -n hw.ncpu`).

### 0.11. Как загружается macOS (Apple Silicon)

На Mac с Apple Silicon нет BIOS или стандартного UEFI GRUB — используется защищённая цепочка загрузки, унаследованная от iOS:

```
Питание → Boot ROM → LLB → iBoot → Ядро XNU + System Extensions → launchd (PID 1) → WindowServer / loginwindow
          аппаратный        проверка   монтирует запечатанный том   запускает демонов   вход пользователя,
          корень доверия    подписи    SSV (/) и том Data           LaunchDaemons       запуск LaunchAgents
```

| Режим загрузки (Apple Silicon) | Как войти | Что это |
|---|---|---|
| **Обычная загрузка** | Нажать кнопку питания | Полная проверка подписей (Full Security), запуск GUI |
| **macOS Recovery (1TR)** | **Удерживать кнопку питания** при включении до появления «Загрузка параметров запуска» | Среда восстановления: Дисковая утилита, Терминал, `csrutil`, сброс пароля |
| **Safe Mode (Безопасный режим)** | В параметрах запуска зажать **Shift** и нажать «Продолжить в безопасном режиме» | Отключает сторонние расширения, `LaunchAgents` и очищает кэши |
| **DFU Mode (Device Firmware Update)** | Специальная комбинация клавиш + подключение по USB-C к другому Mac | Низкоуровневое восстановление прошивки iBoot и ОС через Apple Configurator |

### 0.12. Файловые системы: APFS, контейнеры, тома и SSV

В macOS основной файловой системой является **APFS (Apple File System)**, спроектированная специально для SSD/NVMe с поддержкой Copy-on-Write, мгновенных снапшотов и нативного шифрования.

```
Физический SSD (/dev/disk0)
 └── APFS Container (disk3 — общий пул свободного места!)
      ├── Macintosh HD        (/)                        ← Read-only, подписанный системный том (SSV)
      ├── Macintosh HD - Data (/System/Volumes/Data)     ← Все твои файлы, программы и настройки
      ├── Preboot             (/System/Volumes/Preboot)  ← Загрузочные файлы и ключи FileVault
      ├── Recovery            (/System/Volumes/Recovery) ← Среда восстановления macOS
      └── VM                  (/System/Volumes/VM)       ← Файлы подкачки (swapfile) и снапшот сна
```

- **Общий пул места (Space Sharing):** все тома внутри одного контейнера APFS делят свободное место динамически — не нужно заранее угадывать, сколько гигабайт отрезать под каждый раздел!
- **Signed System Volume (SSV):** системный том `/` смонтирован **только для чтения** и запечатан криптографическим хэш-деревом (Merkle tree). Даже пользователь `root` с отключённым SIP не пишет напрямую в `/`. Все изменяемые папки (`/Users`, `/Applications`, `/Library`, `/opt`, `/usr/local`, `/private`) физически лежат на томе `/System/Volumes/Data` и прозрачно отображаются в корне через **firmlinks**.

| ФС | Где применяется | Особенности в macOS |
|---|---|---|
| **APFS** | Стандарт для всех современных Mac | Снапшоты, клоны (`cp -c`), общее место томов, шифрование FileVault |
| **HFS+ (Mac OS Extended)** | Старые Mac, внешние HDD | Поддерживается для чтения и записи |
| **exFAT / FAT32** | Флешки и внешние диски для обмена с Windows/Linux | Чтение и запись из коробки, нет прав Unix |
| **NTFS** | Диски Windows | Из коробки в macOS работает **только на чтение** (для записи нужны драйверы/FUSE) |

### 0.13. Пакеты и установка программ: Homebrew, `.dmg`, `.pkg`, App Store

В macOS программы устанавливаются четырьмя основными способами:

1. **Homebrew (`brew`)** — де-факто стандартный пакетный менеджер для macOS:
   - **Formulae** (`brew install wget jq ripgrep`) — консольные утилиты и библиотеки. На Apple Silicon ставятся в изолированный каталог **`/opt/homebrew`** (на Intel — в `/usr/local`), не засоряя систему и не требуя `sudo`!
   - **Casks** (`brew install --cask iterm2 visual-studio-code docker`) — обычные графические приложения macOS (`.app`), которые скачиваются с официальных сайтов разработчиков и кладутся в `/Applications`.
2. **Образы дисков (`.dmg`)** — виртуальный диск, который монтируется в `/Volumes`, после чего папка `App.app` просто копируется в `/Applications`.
3. **Установочные пакеты (`.pkg`)** — архивы для системного установщика (`installer`), которые могут выполнять post-install скрипты и класть файлы в `/Library`. Список всех установленных `.pkg` хранится в базе `pkgutil --pkgs`.
4. **Mac App Store** — установка подписанных и упакованных в песочницу приложений (из терминала управляется утилитой **`mas`**).

### 0.14. Сеть: минимум теории и интерфейсы macOS

| Понятие | Суть |
|---|---|
| **IP-адрес и CIDR** | Адрес узла: `192.168.1.10/24` (`255.255.255.0` = 254 адреса), `fe80::...` (IPv6) |
| **Шлюз (router / gateway)** | Роутер, через который трафик уходит во внешний мир (`route -n get default`) |
| **DNS и mDNSResponder** | В macOS за DNS и локальное обнаружение устройств отвечает демон `mDNSResponder` |
| **Bonjour (mDNS)** | Обращение к любому Mac в локальной сети по имени `MacBook-Pro.local` на порту `5353/UDP` |

**Сетевые интерфейсы в macOS (`ifconfig`):**

| Интерфейс | Что это |
|---|---|
| `lo0` | Loopback (`127.0.0.1`, `::1`) — сам компьютер |
| `en0` | Основной интерфейс (на MacBook это всегда **Wi-Fi**, на настольных Mac — первый Ethernet) |
| `en1`, `en2`… | Дополнительные порты Ethernet / Thunderbolt Bridge |
| `awdl0` | **Apple Wireless Direct Link** — пиринговая Wi-Fi сеть для AirDrop, AirPlay и Handoff |
| `llw0` | **Low Latency WLAN** — интерфейс с низкой задержкой для аудио/видео и Continuity |
| `utun0`…`utunN` | Туннели: VPN (WireGuard, OpenVPN), а также системные туннели iCloud Private Relay и Back to My Mac |
| `bridge0`, `bridge100` | Виртуальные сетевые мосты (используются виртуальными машинами и Общим интернетом) |

**Частые порты (включая специфичные для macOS):**

| Порт | Служба | Порт | Служба |
|:---:|---|:---:|---|
| 22 | SSH (Remote Login) | 3306 / 5432 | MySQL / PostgreSQL |
| 53 | DNS | 5000 / 7000 | **AirPlay Receiver** (`ControlCenter`) |
| 80 / 443 | HTTP / HTTPS | 5353 (UDP) | **Bonjour / mDNS** |
| 445 | SMB (Общий доступ к файлам) | 5900 | **Screen Sharing** (VNC) |

> 💡 **Частая ловушка на Mac:** пытаешься запустить локальный сервер (например, Flask или Docker) на порту `5000` или `7000`, а порт уже занят процессом `ControlCenter`! Это встроенный **Приёмник AirPlay** (AirPlay Receiver). Отключить его можно в *Системные настройки → Основные → AirDrop и Handoff → Приёмник AirPlay*.

### 0.15. Как работают SSH-ключи и связка ключей macOS Keychain

```
Твой Mac                                       Сервер
~/.ssh/id_ed25519      (приватный ключ)
  └── пароль от ключа хранится в macOS Keychain (разблокируется по Touch ID!)
~/.ssh/id_ed25519.pub  ───── ssh-copy-id ────▶ ~/.ssh/authorized_keys
```

В macOS встроенный `ssh-agent` интегрирован с системной **Связкой ключей (Keychain)**: достаточно один раз добавить зашифрованный паролем ключ командой `ssh-add --apple-use-keychain ~/.ssh/id_ed25519` и прописать `UseKeychain yes` в `~/.ssh/config`, чтобы macOS автоматически подставляла passphrase после входа в систему, не спрашивая его каждый раз. А для максимальной защиты приватный SSH-ключ можно хранить прямо внутри аппаратного чипа **Secure Enclave** (через `sc_auth` или утилиту **Secretive**), подтверждая каждое SSH-подключение отпечатком пальца **Touch ID**!

## 🟢 5. Поиск: find, mdfind (Spotlight), grep

### `find` — классический поиск по дереву каталогов

> ⚠️ В BSD `find` (на macOS) **путь поиска указывается обязательно** перед опциями (`find . -name ...`).

```bash
find . -name "*.log"                  # по имени (с учётом регистра)
find . -iname "readme*"               # без учёта регистра
find ~ -type f -size +100M            # файлы больше 100 МБ (+100M, +500k, +2G)
find . -type d -name node_modules     # только папки
find . -mtime -1                      # изменены за последние сутки
find . -mmin -30                      # за последние 30 минут
find . -Btime -1                      # 💡 созданы (Birth time в APFS) за последние сутки
find . -empty                         # пустые файлы и папки
find . -user alex                     # принадлежат пользователю
find . -perm 0777                     # с правами 777
find . -name "*.DS_Store" -delete     # 🔴 найти и удалить все .DS_Store в текущей папке
find . -name "*.sh" -exec chmod +x {} +     # выполнить команду для найденных
find . -type f -name "*.js" -print0 | xargs -0 wc -l   # посчитать строки во всех .js (безопасно с пробелами)
```

### `mdfind` — мгновенный поиск через индекс Spotlight 💡

Вместо `locate` в macOS есть мощнейшая утилита **`mdfind`**, которая ищет мгновенно по живому индексу **Spotlight** — как по именам файлов, так и по их содержимому и метаданным (EXIF фото, авторы PDF, откуда скачан файл):

```bash
mdfind -name "nginx.conf"                                  # мгновенный поиск по имени файла на всём Mac
mdfind -onlyin ~/Projects "TODO"                           # найти слово "TODO" внутри файлов в папке ~/Projects
mdfind "kMDItemContentType == 'com.adobe.pdf'"             # все PDF-документы
mdfind "kMDItemWhereFroms == '*github.com*'"               # файлы, скачанные с GitHub!
mdfind "kMDItemFSContentChangeDate >= \$time.today"        # файлы, изменённые сегодня
mdutil -s /                                                # статус индексации Spotlight (mdutil -E / — перестроить индекс)
```

*(Если всё же нужен классический `locate`: база создаётся командой `sudo launchctl load -w /System/Library/LaunchDaemons/com.apple.locate.plist`).*

### `grep` — поиск текста внутри файлов

| Команда | Что делает |
|---|---|
| `grep "error" file.log` | Строки со словом |
| `grep -i "error" file.log` | Без учёта регистра |
| `grep -r "TODO" .` | Рекурсивно по папке |
| `grep -rn "TODO" .` | + номера строк |
| `grep -rl "TODO" .` | Только имена файлов |
| `grep -v "debug" file.log` | Строки **без** совпадения |
| `grep -c "error" file.log` | Количество совпавших строк |
| `grep -w "cat" file.log` | Целое слово (не `category`) |

## 🟢 6. Права доступа: chmod, chown, ACL и xattr

### Как читать `ls -leO@` в macOS

```
-rwxr-xr--@  1  alex  staff  uchg  4096  12 Oct 10:00  script.sh
│└┬┘└┬┘└┬┘│       │     │     └── флаг файла BSD (uchg = immutable, hidden = скрытый)
│ │  │  │ └── @ = есть расширенные атрибуты (xattr), + = есть правила ACL
│ │  │  └──── остальные (others): r--
│ │  └─────── группа (group, по умолчанию staff): r-x
│ └────────── владелец (user): rwx
└──────────── тип: - файл, d папка, l симлинк
```

### Числовые права

| Цифра | Права | Значение |
|:---:|:---:|---|
| 7 | `rwx` | чтение + запись + выполнение |
| 6 | `rw-` | чтение + запись |
| 5 | `r-x` | чтение + выполнение |
| 4 | `r--` | только чтение |
| 0 | `---` | нет прав |

**r = 4, w = 2, x = 1** — просто складывай.

### Частые комбинации

| Права | Для чего |
|:---:|---|
| `644` | Обычные файлы (`rw-r--r--`) |
| `755` | Скрипты, программы и папки (`rwxr-xr-x`) |
| `600` | Приватные файлы, SSH-ключи (`rw-------`) |
| `700` | Приватные папки, `~/.ssh` (`rwx------`) |
| `777` | 🔴 Всем всё — почти никогда не нужно |

### Команды `chmod` и `chown`

```bash
chmod 755 script.sh           # числовой способ
chmod +x script.sh            # добавить выполнение всем
chmod u+x,g-w,o-r file        # символьный способ (u,g,o,a / + - =)
chmod -R 755 dir/             # рекурсивно
chown alex file               # сменить владельца
chown alex:staff file         # сменить владельца и группу (в macOS основная группа — staff)
sudo chown -R $(whoami):staff /usr/local/share
chgrp admin file              # сменить группу
umask                         # маска прав по умолчанию (022)
```

### Расширенные атрибуты (`xattr`), флаги (`chflags`) и ACL в macOS 🟡

В macOS стандартные права Unix дополняются тремя механизмами:

```bash
# 1. Расширенные атрибуты (xattr) — символ @ в ls -l
xattr -l file.dmg                              # посмотреть все xattr и их значения
xattr -d com.apple.quarantine App.app          # убрать метку карантина с одного файла
sudo xattr -rd com.apple.quarantine /Applications/App.app  # 💡 починить «Приложение повреждено / не проверено»
xattr -c file.txt                              # очистить все расширенные атрибуты файла

# 2. Флаги файлов (chflags) — колонка при ls -lO
chflags hidden secret_folder                   # скрыть папку в Finder (без точки в имени!)
chflags nohidden ~/Library                     # 💡 сделать папку ~/Library всегда видимой в Finder
chflags uchg important.txt                     # поставить «Замок» (Защищён) — нельзя удалить даже владельцу
chflags nouchg important.txt                   # снять защиту от изменений

# 3. Списки контроля доступа (ACL) — символ + в ls -l
ls -le ~/Desktop                               # увидеть ACL (например: 0: group:everyone deny delete)
chmod +a "user:bob allow read,write,append" shared.txt   # дать bob доступ к файлу
chmod -a# 0 shared.txt                         # удалить правило ACL с номером 0
chmod -N shared.txt                            # удалить все ACL с файла
```

## 🟢 7. Пользователи и группы: Open Directory, dscl, sudo

В macOS нет команд `useradd`, `usermod` или `adduser`. Все локальные пользователи и группы хранятся в базе **Open Directory** (`/var/db/dslocal/nodes/Default`) и управляются через **`sysadminctl`**, **`dscl`** (Directory Service Command Line) и **`dseditgroup`**.

| Команда | Что делает |
|---|---|
| `whoami` | Текущий пользователь |
| `id` | UID, GID и список всех групп пользователя |
| `groups alex` | Группы пользователя |
| `who` / `w` | Кто сейчас залогинен в системе (GUI и терминалы) |
| `last -10` | История последних 10 входов и перезагрузок |
| `sudo команда` | Выполнить команду от `root` (доступно группе `admin`) |
| `sudo -i` / `sudo -s` | Интерактивная `root`-сессия |
| `su - alex` | Переключиться на другого пользователя |
| `dscl . -list /Users \| grep -v '^_'` | Список всех реальных пользователей (без служебных `_daemon`) |
| `dscl . -list /Users UniqueID` | Показать всех пользователей и их UID |
| `dscl . -read /Users/alex` | Подробный профиль пользователя в Open Directory |
| `sudo sysadminctl -addUser bob -fullName "Bob" -password -` | Создать нового пользователя (пароль спросит интерактивно) |
| `sudo sysadminctl -addUser bob -password - -admin` | Создать нового пользователя с правами администратора (`sudo`) |
| `sudo sysadminctl -deleteUser bob` | 🔴 Удалить пользователя и его домашнюю папку |
| `passwd` / `sudo dscl . -passwd /Users/bob` | Сменить свой пароль / пароль другого пользователя |
| `chsh -s /bin/zsh` | Сменить оболочку по умолчанию (список разрешённых — в `/etc/shells`) |
| `sudo dseditgroup -o edit -a bob -t user admin` | Добавить пользователя `bob` в группу `admin` (аналог `usermod -aG sudo`) |
| `sudo dseditgroup -o edit -d bob -t user admin` | Убрать пользователя `bob` из группы `admin` |
| `sudo dseditgroup -o create devs` | Создать новую группу `devs` |
| `dsmemberutil checkmembership -U alex -G admin` | Проверить, входит ли пользователь в группу |
| `sudo visudo` | Безопасно редактировать `/etc/sudoers` (лучше класть файлы в `/etc/sudoers.d/`) |

### 💡 Включить Touch ID для `sudo` в Терминале за 10 секунд

Начиная с macOS Sonoma, для этого предусмотрен специальный файл `/etc/pam.d/sudo_local`, который **не сбрасывается** при обновлениях macOS:

```bash
sed 's/^#auth/auth/' /etc/pam.d/sudo_local.template | sudo tee /etc/pam.d/sudo_local
```

Теперь при вызове `sudo` вместо ввода пароля можно просто приложить палец к **Touch ID** (или подтвердить с Apple Watch)!

### Фоновые задачи и суперсила `Ctrl+T` (`SIGINFO`)

```bash
cmd &            # запустить в фоне

bg               # продолжить остановленную задачу в фоне
```

> 💡 **Эксклюзив BSD / macOS — клавиши `Ctrl+T` (`SIGINFO`):** если ты запустил долгое копирование `cp`, запись образа через `dd`, архивацию или `sleep` и забыл включить прогресс-бар, просто нажми **`Ctrl+T`** прямо во время выполнения! ## 🟡 10. Диски, контейнеры APFS и файловые системы

В macOS управление дисками, разделами и контейнерами APFS сосредоточено в мощной утилите **`diskutil`** (а для образов дисков `.dmg` — **`hdiutil`**).

| Команда | Что делает |
|---|---|
| `df -h` | Свободное место на всех смонтированных томах |
| `df -i` | Использование inode |
| `du -sh *` | Размер каждого файла и папки в текущей директории |
| `sudo du -hd 1 /System/Volumes/Data \| sort -h` | 💡 Что занимает место на диске (в BSD `du` глубина задаётся `-d 1`, а не `--max-depth=1`) |
| `ncdu /System/Volumes/Data` | Удобный интерактивный анализатор места на диске (`brew install ncdu`) |
| `diskutil list` | Список всех физических дисков, разделов и контейнеров APFS (аналог `lsblk`) |
| `diskutil apfs list` | Дерево контейнеров и томов APFS |
| `diskutil info disk0` / `diskutil info /` | Подробная информация о диске или томе (UUID, ФС, SMART-статус, скорость шины) |
| `diskutil mount disk2s1` / `diskutil unmount disk2s1` | Смонтировать / размонтировать раздел |
| `diskutil unmountDisk disk2` | Размонтировать все разделы внешнего диска |
| `diskutil eject disk2` | Безопасно извлечь внешний диск или флешку |
| `diskutil verifyVolume /` / `diskutil repairVolume disk2s1` | Проверить / починить файловую систему (обёртка над `fsck_apfs`) |
| `diskutil eraseDisk APFS "Backup" GPT disk2` | 🔴 Полностью стереть диск `disk2` и отформатировать в APFS |
| `diskutil eraseDisk ExFAT "Flash" MBR disk2` | 🔴 Отформатировать флешку `disk2` в ExFAT (совместимо с macOS, Windows, Linux) |
| `hdiutil attach image.dmg` / `hdiutil detach /Volumes/Img` | Смонтировать / отключить `.dmg`-образ из терминала |

### Добавить отдельный том APFS без переразметки диска

Так как все тома внутри контейнера APFS делят общее место, ты можешь за секунду создать отдельный том (например, чувствительный к регистру для Linux-проектов или с лимитом размера):

```bash
# Создать новый том "Code" (Case-sensitive APFS) с квотой 50 ГБ внутри основного контейнера disk3:
sudo diskutil apfs addVolume disk3 "Case-sensitive APFS" Code -quota 50g
# Том сразу появится в /Volumes/Code! Удалить том:
sudo diskutil apfs deleteVolume /Volumes/Code
```

## 🟢 11. Сеть

В macOS нет команд `ip` и `ss` из пакета `iproute2` (при желании похожий синтаксис даёт `brew install iproute2mac`). Родные инструменты macOS — это `ifconfig`, `networksetup`, `scutil`, `netstat`, `lsof` и `networkQuality`.

| Команда | Что делает |
|---|---|
| `ifconfig` | Все сетевые интерфейсы, их статус, MAC и IP-адреса |
| `ipconfig getifaddr en0` | 💡 Быстро вывести только локальный IPv4-адрес Wi-Fi / Ethernet (`en0`) |
| `ipconfig getpacket en0` | Показать ответ DHCP-сервера (выданный IP, маску, роутер, DNS) |
| `route -n get default` | Узнать IP-адрес шлюза по умолчанию (роутера) и интерфейс |
| `netstat -rn -f inet` | Таблица маршрутизации IPv4 |
| `sudo lsof -iTCP -sTCP:LISTEN -n -P` | 💡 Открытые TCP-порты и какие процессы их слушают (замена `ss -tulpn`) |
| `netstat -anv -p tcp \| grep LISTEN` | Быстрый список слушающих TCP-портов с PID процессов |
| `ping -c 4 8.8.8.8` | Проверка связи (4 пакета) |
| `traceroute google.com` / `mtr google.com` | Маршрут до хоста (`mtr` ставится через `brew install mtr`) |
| `networkQuality` | 💡 Встроенный в macOS тест скорости интернета (Мбит/с) и отзывчивости сети (RPM) |
| `curl -I https://example.com` | Получить только HTTP-заголовки ответа |
| `curl -LO URL` | Скачать файл (с переходом по редиректам `-L`) |
| `curl -s ifconfig.me` | Узнать свой внешний (публичный) IP-адрес |
| `dig example.com` / `dig +short example.com MX` | DNS-запрос / получить только MX-записи |
| `host example.com` / `nslookup example.com` | Простая проверка DNS |
| `scutil --dns` | 💡 Реальные настройки DNS-резолвера macOS (включая VPN и split-DNS) |
| `sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder` | 💡 Сбросить DNS-кэш в macOS |
| `networksetup -listallhardwareports` | Соответствие имён портов (`Wi-Fi`, `Ethernet`) и интерфейсов (`en0`, `en1`) |
| `networksetup -getdnsservers Wi-Fi` | Посмотреть DNS-серверы для Wi-Fi |
| `sudo networksetup -setdnsservers Wi-Fi 1.1.1.1 8.8.8.8` | Задать DNS-серверы для Wi-Fi (`empty` — вернуть автоматические от DHCP) |
| `sudo networksetup -setairportpower en0 off` / `on` | Выключить / включить Wi-Fi из терминала |
| `system_profiler SPAirPortDataType` / `sudo wdutil info` | Подробная диагностика Wi-Fi: канал, частота, RSSI, шум, скорость (MCS) |
| `nc -zv host 443` | Проверить, открыт ли порт 443 на удалённом хосте |
| `sudo tcpdump -i en0 -nn port 80` | 🟡 Перехват сетевого трафика |

## 🟢 12. SSH, SCP, rsync и связка ключей Keychain

```bash
ssh user@host                          # подключиться к серверу
ssh -p 2222 user@host                  # на нестандартный порт
ssh -i ~/.ssh/key user@host            # с конкретным приватным ключом
ssh-keygen -t ed25519 -C "me@mac"      # создать современную пару ключей Ed25519
ssh-copy-id user@host                  # скопировать публичный ключ на сервер
ssh user@host 'df -h'                  # выполнить команду удалённо и выйти

scp file.txt user@host:/tmp/           # скопировать файл на сервер
scp user@host:/var/log/app.log .       # скачать файл с сервера
scp -r dir/ user@host:~/               # скопировать папку рекурсивно

rsync -avz dir/ user@host:~/dir/       # синхронизация (передаёт только изменения)
rsync -avz --delete src/ dst/          # 🔴 удалить в dst то, чего нет в src
rsync -avzP big.iso user@host:~        # с прогрессом и докачкой при обрыве

ssh -L 8080:localhost:80 user@host     # 🟡 проброс порта: локальный 8080 → удалённый 80
ssh -D 1080 user@host                  # 🟡 поднять локальный SOCKS5-прокси на порту 1080
ssh -J jump@bastion user@internal      # 🟡 подключение через промежуточный хост (bastion)
```

### `~/.ssh/config` с поддержкой macOS Keychain 💡

Чтобы macOS хранила пароли от твоих SSH-ключей в системной Связке ключей (Keychain) и подгружала их автоматически:

```sshconfig
Host *
    AddKeysToAgent yes
    UseKeychain yes
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60

Host prod
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/prod_ed25519
```

Добавь ключ в Keychain один раз:

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

Теперь достаточно ввести `ssh prod`.

> 💡 У `rsync` важен слеш в конце источника: `rsync -a dir/ dst/` копирует **содержимое** папки `dir`, а `rsync -a dir dst/` — **саму папку** `dir` внутрь `dst`.

## 🟢 13. Архивы, сжатие и образы дисков

| Команда | Что делает |
|---|---|
| `tar -czvf arch.tar.gz dir/` | Создать `.tar.gz` |

| `tar -xzvf arch.tar.gz -C /tmp` | Распаковать в указанную папку |

| `zip -r arch.zip dir/ -x "*.DS_Store" -x "__MACOSX*"` | Создать чистый `.zip` без служебного мусора macOS |

**Как запомнить ключи tar:** `c` — create, `x` — extract, `t` — list, `z` — gzip, `J` — xz, `j` — bzip2, `v` — verbose, `f` — file.

## 🟢 15. Launchd и службы (launchctl, brew services)

В macOS вместо `systemd` за все фоновые процессы отвечает **`launchd`** (PID 1). Задания описываются в XML-файлах `.plist`:

| Каталог | Кто запускает и когда |
|---|---|
| `~/Library/LaunchAgents` | От имени **текущего пользователя** при его входе в систему (GUI) |
| `/Library/LaunchAgents` | От имени **любого пользователя** при его входе в систему |
| `/Library/LaunchDaemons` | От имени **`root`** (или указанного `UserName`) при загрузке Mac (даже без входа пользователя) |
| `/System/Library/Launch*` | Системные службы самой macOS (защищены SIP, не трогать) |

### Управление службами через `brew services` (для пакетов Homebrew)

Если ты установил `postgresql`, `redis`, `nginx` или `dnsmasq` через Homebrew, проще всего управлять ими так:

| Команда | Что делает |
|---|---|
| `brew services list` | Список всех служб Homebrew и их статус |
| `brew services start nginx` | Запустить службу и **включить автозапуск** при входе |
| `brew services run nginx` | Запустить разово (без добавления в автозапуск) |
| `brew services stop nginx` | Остановить службу и убрать из автозапуска |
| `brew services restart nginx` | Перезапустить службу |

### Нативное управление через `launchctl`

| Команда | Что делает |
|---|---|
| `launchctl list` | Список запущенных пользовательских служб (колонки: `PID`, `LastExitStatus`, `Label`) |
| `sudo launchctl list \| grep ssh` | Найти системную службу |
| `launchctl print gui/$(id -u)/com.user.myapp` | Подробный статус пользовательской службы (для системной: `system/имя`) |
| `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.user.myapp.plist` | Зарегистрировать и запустить свой агент |
| `launchctl bootout gui/$(id -u)/com.user.myapp` | Остановить и выгрузить свой агент |
| `launchctl kickstart -k gui/$(id -u)/com.user.myapp` | Принудительно перезапустить службу прямо сейчас |
| `sudo shutdown -r now` / `sudo shutdown -h now` | Перезагрузить / выключить Mac из терминала |

## 🟢 16. Логи и Unified Logging (log)

В macOS вместо `journalctl` работает единая высокопроизводительная система логирования **Unified Logging** (графический интерфейс — `Console.app`, консольная утилита — **`log`**).

| Команда | Что делает |
|---|---|
| `log stream` | Поток всех логов системы в реальном времени (очень много событий!) |
| `log stream --level error` | В реальном времени — только ошибки (`default`, `info`, `debug`, `error`, `fault`) |
| `log stream --process sshd` | Следить в реальном времени за конкретным процессом |
| `log stream --predicate 'subsystem == "com.apple.network"'` | Следить за конкретной подсистемой Apple |
| `log show --last 15m` | Показать логи за последние 15 минут (`1h`, `1d`) |

| `log show --predicate 'eventMessage contains "error"' --last 30m` | Поиск по тексту сообщения за последние 30 минут |
| `log show --predicate 'eventMessage contains "Previous shutdown cause"' --last 24h` | 💡 Узнать причину последнего выключения / внезапной перезагрузки |
| `sudo dmesg \| tail -50` | Буфер сообщений ядра XNU |
| `log stats --overview` | Статистика объёма логов по процессам и подсистемам |

**Классические текстовые логи и отчёты о сбоях в macOS:**

## 🟡 17. Обработка текста: sed, awk, cut, sort, plutil

### `sed` — поиск и замена (с учётом BSD-особенностей!)

> 🔴 **Главное отличие macOS `sed` от Linux:** ключ `-i` (редактирование файла на месте) в BSD `sed` **требует обязательного аргумента** для расширения бэкапа. Чтобы изменить файл без создания бэкапа, передай пустые кавычки: `sed -i '' 's/old/new/g' file`!

```bash
sed 's/old/new/' file             # заменить первое вхождение в каждой строке (вывод на экран)
sed 's/old/new/g' file            # заменить все вхождения
sed -i '' 's/old/new/g' file      # 🔴 изменить файл на месте БЕЗ резервной копии (macOS / BSD!)
sed -i '.bak' 's/old/new/g' file  # изменить файл на месте, сохранив копию file.bak
sed -n '10,20p' file              # вывести только строки с 10 по 20
sed '/^#/d' file                  # удалить строки комментариев
sed '/^$/d' file                  # удалить пустые строки
```

### `awk` — работа с колонками

```bash
awk '{print $1}' file                     # первая колонка (разделитель — пробелы/табы)
awk -F: '{print $1, $7}' /etc/passwd      # задать разделитель ":"
awk '$3 > 100' file                       # строки, где 3-я колонка больше 100
awk '{sum += $2} END {print sum}' file    # посчитать сумму 2-й колонки
awk 'NR==5' file                          # вывести ровно 5-ю строку
awk '{print NF}' file                     # количество колонок в каждой строке
```

### Остальные инструменты и работа с JSON / Plist

| Команда | Что делает |
|---|---|
| `cut -d, -f1,3 file.csv` | Вырезать колонки 1 и 3 из CSV |
| `sort file` | Отсортировать строки по алфавиту |
| `sort -n` / `sort -h` | Числовая сортировка / по размерам (`1K`, `2M`, `3G`) |
| `sort -rn -k2` | По 2-й колонке, численно, по убыванию |

## 🟢 18. Перенаправление, пайпы, xargs и буфер обмена

| Синтаксис | Что делает |
|---|---|
| `cmd > file` | `stdout` в файл (перезаписать) |
| `cmd >> file` | `stdout` в файл (дописать в конец) |
| `cmd 2> err.log` | `stderr` (ошибки) в файл |
| `cmd > out.log 2>&1` | `stdout` и `stderr` в один файл (работает везде) |
| `cmd &> out.log` | То же, короче (Zsh и Bash) |
| `cmd > /dev/null 2>&1` | Полностью заглушить весь вывод |
| `cmd < file` | Подать содержимое файла на `stdin` команды |
| `cmd1 \| cmd2` | Вывод первой команды подать на вход второй |
| `cmd \| pbcopy` | 💡 Записать вывод команды прямо в буфер обмена macOS (`Cmd+V`) |
| `pbpaste \| cmd` | 💡 Подать содержимое буфера обмена macOS на вход команде |
| `cmd1 && cmd2` | Выполнить вторую **только если** первая завершилась успешно (`0`) |
| `cmd1 \|\| cmd2` | Выполнить вторую **только если** первая завершилась с ошибкой |
| `cmd1 ; cmd2` | Выполнить по очереди в любом случае |
| `$(cmd)` | Подставить вывод команды как строку |
| `<(cmd)` | Подставить вывод команды как временный файл: `diff -u <(ls dir1) <(ls dir2)` |

```bash
cat urls.txt | xargs -n1 curl -sLO                # скачивать по одному URL
find . -name "*.log" -print0 | xargs -0 rm -f     # безопасно для файлов с пробелами в именах
cat hosts.txt | xargs -P4 -I{} ping -c1 -W1000 {} # 4 параллельных пинга
```

> 💡 В отличие от GNU `xargs`, в BSD `xargs` на macOS **не нужен** (и не существует) ключ `-r` (`--no-run-if-empty`): если на вход пришёл пустой поток, `xargs` в macOS по умолчанию и так не запустит команду.

## 🟡 19. Zsh и Bash: переменные и скрипты

### Шаблон надёжного скрипта

```bash
#!/usr/bin/env bash
set -euo pipefail   # падать на ошибках (-e), неопределённых переменных (-u) и ошибках внутри пайпов (-o pipefail)

NAME="${1:-macOS}"  # первый аргумент или значение по умолчанию
echo "Привет, $NAME!"
```

```bash
chmod +x script.sh && ./script.sh Мир
```

> 💡 Помни: в macOS системный `/bin/bash` — версии **3.2**. Если в скрипте нужны возможности современных оболочек (ассоциативные массивы, глоббинг `**`), пиши в первой строке `#!/usr/bin/env zsh` (Zsh 5.9 встроен в каждую macOS) или установи свежий Bash (`brew install bash`).

### Переменные

| Синтаксис | Значение |
|---|---|
| `VAR=value` | Присвоить значение (без пробелов вокруг `=`!) |
| `export VAR=value` | Сделать переменную доступной дочерним процессам |
| `$VAR` / `"${VAR}"` | Использовать значение (в Bash всегда бери в двойные кавычки) |
| `$0` | Имя запущенного скрипта |
| `$1`…`$9` | Позиционные аргументы скрипта или функции |
| `$#` | Количество переданных аргументов |
| `"$@"` | Все аргументы как отдельные строки |

| `$((a + b))` | Целочисленная арифметика |

## 🟢 22. Планировщики задач: launchd и cron

В macOS классический `cron` поддерживается, но Apple рекомендует использовать **`launchd`** (`StartCalendarInterval` в `LaunchAgents`), так как `launchd` **умеет запускать пропущенную задачу после того, как Mac проснулся** (если в назначенное время крышка ноутбука была закрыта), а `cron` пропущенный запуск просто проигнорирует.

### Классический `cron`

```bash
crontab -e        # редактировать свои задачи
crontab -l        # посмотреть список задач
crontab -r        # 🔴 удалить все свои задачи cron
```

```
┌───────── минута (0–59)
│ ┌─────── час (0–23)
│ │ ┌───── день месяца (1–31)
│ │ │ ┌─── месяц (1–12)
│ │ │ │ ┌─ день недели (0–7, 0 и 7 = воскресенье)
│ │ │ │ │
* * * * *  команда
```

| Расписание | Когда выполняется |
|---|---|
| `*/5 * * * *` | Каждые 5 минут |
| `0 * * * *` | Каждый час в 00 минут |
| `0 3 * * *` | Каждый день в 03:00 |
| `0 9 * * 1-5` | По будням в 09:00 |
| `0 0 1 * *` | Первого числа каждого месяца в полночь |
| `@reboot` | При загрузке системы |

```bash
0 3 * * * /Users/alex/bin/backup.sh >> /tmp/backup.log 2>&1
```

> ⚠️ **Важно для macOS:** 1) В `cron` минимальный `PATH` (`/usr/bin:/bin`) — всегда пиши полные пути (`/opt/homebrew/bin/...`) или задай `PATH=/opt/homebrew/bin:/usr/bin:/bin` в первой строке `crontab`. 2) Если скрипт обращается к `~/Desktop`, `~/Documents` или внешним дискам, выдай `/usr/sbin/cron` разрешение **Полный доступ к диску (Full Disk Access)** в *Системные настройки → Конфиденциальность и безопасность*.

## 🟡 23. Файрвол: Application Firewall и Packet Filter (pf)

В macOS встроены сразу **два** независимых файрвола:
1. **Application Firewall (`socketfilterfw`)** — работает на уровне приложений и цифровых подписей (это тот самый переключатель в *Системные настройки → Сеть → Брандмауэр*).
2. **Packet Filter (`pf` / `pfctl`)** — мощный пакетный файрвол на уровне ядра (портирован из OpenBSD), фильтрующий IP-пакеты, порты и NAT.

### 1. Application Firewall (`socketfilterfw`)

| Действие | Команда |
|---|---|
| Статус файрвола | `/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` |
| Включить / выключить | `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on` (`off`) |
| Включить режим невидимости (Stealth Mode — не отвечать на ping и сканы) | `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setstealthmode on` |
| Список всех правил для приложений | `/usr/libexec/ApplicationFirewall/socketfilterfw --listapps` |
| Заблокировать входящие соединения для приложения | `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --blockapp /Applications/App.app` |
| Разрешить приложение | `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp /Applications/App.app` |

### 2. Пакетный фильтр ядра (`pfctl`)

Конфигурация лежит в `/etc/pf.conf` и `/etc/pf.anchors/`.

```bash
sudo pfctl -s info                        # статус pf (Enabled / Disabled) и статистика пакетов
sudo pfctl -s rules                       # показать активные правила фильтрации (-sr)
sudo pfctl -s nat                         # показать правила NAT и проброса портов (-sn)
sudo pfctl -s states                      # таблица текущих активных соединений (-ss)
sudo pfctl -nf /etc/pf.conf               # проверить синтаксис конфига, не применяя его
sudo pfctl -ef /etc/pf.conf               # включить pf и загрузить правила
sudo pfctl -d                             # выключить pf
```

> 💡 Встроенные файрволы macOS по умолчанию контролируют **входящие** соединения. Чтобы контролировать, какие программы на Mac лезут в интернет (**исходящие** соединения), используй бесплатный open-source файрвол **[LuLu](https://objective-see.org/products/lulu.html)** (`brew install --cask lulu`) или **Little Snitch**.

## 🟢 24. Структура каталогов macOS

В macOS классическая иерархия UNIX объединена с иерархией NeXTSTEP/Aqua:

| Каталог | Назначение |
|---|---|
| `/` | Корень файловой системы (запечатанный read-only том SSV) |
| `/Applications` | Установленные графические программы (`.app`) для всех пользователей |
| `/System` | Операционная система macOS, системные фреймворки и ядро (защищено SIP) |
| `/System/Volumes/Data` | Том данных, где реально хранятся все изменяемые файлы (подключён через firmlinks) |
| `/Library` | Общесистемные настройки, плагины, шрифты, кэши и `LaunchDaemons` |
| `/Users` | Домашние папки пользователей (`/Users/alex`) |
| `~/Library` | Личные настройки приложений (`Preferences`), `Application Support`, кэши (`Caches`) и `LaunchAgents` |
| `/Volumes` | Точки монтирования внешних дисков, флешек, сетевых папок и `.dmg`-образов |
| `/opt/homebrew` | Пакеты, установленные через Homebrew на Apple Silicon |
| `/usr/local` | Программы, установленные вручную (и пакеты Homebrew на Intel Mac) |
| `/bin`, `/usr/bin`, `/sbin`, `/usr/sbin` | Базовые и системные UNIX-утилиты (защищены SIP) |
| `/etc`, `/var`, `/tmp` | Симлинки на `/private/etc` (конфиги), `/private/var` (логи, базы, спул) и `/private/tmp` (очищается при перезагрузке) |
| `/dev` | Файлы устройств (`/dev/disk0`, `/dev/null`, `/dev/urandom`) |
| `/Cores` | Дампы памяти процессов при аварийном завершении (core dumps) |

**Четыре уровня (домена) в macOS:** почти любой ресурс (например, шрифты `Fonts` или агенты `LaunchAgents`) ищется по цепочке:
`~/Library` (только для тебя) → `/Library` (для всех пользователей этого Mac) → `/Network/Library` (в корпоративной сети) → `/System/Library` (вшито в саму macOS).

## 🟡 26. Zsh и Bash для профи: массивы, раскрытие параметров, trap

### Раскрытие параметров (без вызова `sed` и `awk`)

Пусть `f="/Users/alex/archive.tar.gz"`:

| Синтаксис | Что делает | Результат |
|---|---|---|
| `${f##*/}` | Убрать самый длинный префикс по шаблону | `archive.tar.gz` (как `basename`) |
| `${f%/*}` | Убрать самый короткий суффикс | `/Users/alex` (как `dirname`) |
| `${f#*.}` | Убрать самый короткий префикс | `tar.gz` |
| `${f%%.*}` | Убрать самый длинный суффикс | `/Users/alex/archive` |
| `${f/alex/root}` | Заменить первое вхождение | `/Users/root/archive.tar.gz` |
| `${f//a/A}` | Заменить все вхождения | `/Users/Alex/Archive.tAr.gz` |
| `${f:0:6}` | Подстрока: с позиции 0, длина 6 | `/Users` |
| `${(U)f}` / `${(L)f}` | В верхний / нижний регистр в **Zsh** (в Bash 4+: `${f^^}` / `${f,,}`) | `/USERS/ALEX/…` |
| `${v:=def}` | Если пусто — присвоить `def` и вернуть его | |
| `${v:?нет значения}` | Если пусто — вывести ошибку и прервать скрипт | |
| `${v:+alt}` | Если **НЕ** пусто — подставить `alt` | |

> 💡 Запомнить легко: на клавиатуре `#` стоит **слева** от `$` — режет **слева** (префикс), `%` стоит **справа** — режет **справа** (суффикс). Двойной символ (`##`, `%%`) — «жадно».

### Массивы и ассоциативные словари

> ⚠️ В системном `/bin/bash` (3.2) на macOS **нет** ассоциативных массивов (`declare -A`) и `mapfile`. Используй для таких скриптов встроенный **`#!/usr/bin/env zsh`** или установи свежий Bash 5 (`brew install bash` → `#!/opt/homebrew/bin/bash`).

```zsh
arr=(one two "three four")      # обычный массив (в Zsh индексы с 1, в Bash — с 0; "${arr[@]}" работает везде!)
echo "${arr[@]}"                # все элементы (всегда в кавычках!)
echo "${#arr[@]}"               # количество элементов
arr+=(five)                     # добавить элемент
for x in "${arr[@]}"; do echo "$x"; done

typeset -A port=([ssh]=22 [http]=80)   # ассоциативный словарь (работает и в Zsh, и в Bash 4+)
port[https]=443
```

### Суперсилы Zsh: Glob Qualifiers (замена `find`) 💡

В интерактивном терминале macOS (Zsh) можно фильтровать файлы прямо в маске:

```zsh
ls -l *(.)            # только обычные файлы в текущей папке (без каталогов)
ls -l *(/)            # только папки
ls -l *(@)            # только символические ссылки
ls -l *(om[1,5])      # 5 самых недавно изменённых файлов
ls -l *(OL[1,5])      # 5 самых больших файлов
ls -l **/*.py(.)      # рекурсивно все .py файлы во всех подпапках
```

### Надёжный скрипт: временные файлы, очистка, ловушки `trap`

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
IFS=$'\n\t'

tmp=$(mktemp -d)                                   # безопасная временная папка в /var/folders/...
trap 'rm -rf "$tmp"' EXIT                          # гарантированно удалится при любом выходе
trap 'echo "Ошибка в строке $LINENO: $BASH_COMMAND" >&2' ERR

log() { printf '[%s] %s\n' "$(date '+%F %T')" "$*" >&2; }
log "Старт работы во временной папке $tmp"
```

### Разбор опций: `getopts`

```bash
usage() { echo "Использование: $0 [-v] [-o файл] аргумент" >&2; exit 2; }
verbose=0; out=/dev/stdout
while getopts ":vo:h" opt; do
  case "$opt" in
    v) verbose=1 ;;
    o) out="$OPTARG" ;;
    h|*) usage ;;
  esac
done
shift $((OPTIND - 1))           # теперь $1 — первый позиционный аргумент
[[ $# -ge 1 ]] || usage
```

| `bash -n script.sh` / `zsh -n script.sh` | Проверить синтаксис, не запуская скрипт |
| `bash -x script.sh` | Печатать каждую команду с раскрытыми аргументами перед выполнением |
| `set -x` … `set +x` | Включить трассировку только на выбранном участке кода |
| `shellcheck script.sh` | Статический анализатор (`brew install shellcheck`) |

### Классические ловушки

| ❌ Плохо | ✅ Хорошо | Почему |
|---|---|---|
| `for f in $(ls *.txt)` | `for f in *.txt` | Имена с пробелами разобьются на куски |
| `while read line` | `while IFS= read -r line` | Иначе съест ведущие пробелы и символ `\` |
| `cd dir; rm -rf *` | `cd dir && rm -rf ./*` | Если `cd` не сработал — удалишь файлы в текущей папке! |
| `rm -rf $DIR/` | `rm -rf "${DIR:?}/"` | При пустой переменной превратится в `rm -rf /` |
| `sed -i 's/a/b/' file` | `sed -i '' 's/a/b/' file` | На macOS BSD `sed` без `''` воспримет `'s/a/b/'` как суффикс бэкапа! |
| `echo $var` | `printf '%s\n' "$var"` | `echo` по-разному трактует `-n` и `\` |

## 🟡 27. APFS: контейнеры, снапшоты, FileVault и AppleRAID

### Как устроена APFS (аналог LVM + Btrfs в мире macOS)

```
 Физический SSD       /dev/disk0
                          │
 Контейнер APFS     /dev/disk3 (общий пул свободных блоков)
            ┌─────────────┼─────────────┬─────────────┐
 Тома APFS  Macintosh HD  Data          Work (Case)   VM (Swap)
            (SSV, R/O)    (/Users, …)   (-quota 50G)  (динамический)
```

В APFS не нужно двигать границы разделов: все тома внутри контейнера делят общее свободное место, при желании для тома можно задать `reserve` (гарантированный минимум) и `quota` (максимальный предел).

| Команда | Что делает |
|---|---|
| `diskutil apfs list` | Показать все контейнеры, тома, занятое место и шифрование |
| `sudo diskutil apfs addVolume disk3 APFS "Dev"` | Мгновенно создать новый том внутри контейнера `disk3` |
| `sudo diskutil apfs addVolume disk3 "Case-sensitive APFS" "LinuxSrc" -quota 30g` | Создать том с учётом регистра и лимитом 30 ГБ |
| `sudo diskutil apfs deleteVolume /Volumes/Dev` | 🔴 Удалить том APFS без затрагивания соседних томов |
| `sudo diskutil apfs resizeContainer disk0s2 0` | Расширить контейнер APFS на всё доступное место диска |

### Локальные снапшоты APFS (`tmutil`) 💡

Даже если внешний диск Time Machine сейчас не подключён, macOS умеет делать мгновенные Copy-on-Write снапшоты состояния диска прямо на внутреннем SSD (например, перед крупным обновлением или экспериментом):

```bash
tmutil localsnapshot                                     # создать мгновенный снапшот прямо сейчас
tmutil listlocalsnapshots /                              # список всех локальных снапшотов
tmutil deletelocalsnapshots 2026-10-12-183000            # удалить конкретный снапшот
sudo tmutil thinlocalsnapshots / 20000000000 4           # 💡 освободить до 20 ГБ места, удалив старые снапшоты!

# Смонтировать снапшот в режиме чтения, чтобы вытащить случайно удалённый час назад файл:
mkdir -p /tmp/snap
sudo mount_apfs -s com.apple.TimeMachine.2026-10-12-183000.local /System/Volumes/Data /tmp/snap
ls /tmp/snap/Users/alex/
sudo umount /tmp/snap
```

### Шифрование дисков: FileVault (`fdesetup`) и шифрованные тома

```bash
fdesetup status                                          # включён ли FileVault (On / Off)
sudo fdesetup list                                       # какие пользователи могут разблокировать диск при загрузке
sudo fdesetup enable                                     # включить полное шифрование диска FileVault
diskutil apfs listCryptoUsers /                          # крипто-пользователи тома APFS
diskutil apfs encryptVolume disk4s1 -user disk           # зашифровать внешний том APFS паролем
diskutil apfs unlockVolume disk4s1                       # разблокировать и смонтировать зашифрованный том
```

### Программный RAID в macOS (`diskutil appleRAID`)

```bash
# Создать зеркало (RAID 1) или страйп (RAID 0) из двух внешних дисков:
sudo diskutil appleRAID create mirror "SafeData" APFS disk2 disk3
sudo diskutil appleRAID list                             # статус RAID-массива
```

### Проверка здоровья SSD (SMART)

```bash
diskutil info disk0 | grep -i "SMART"                    # быстрый статус (Verified)
smartctl -a disk0                                        # подробный отчёт: износ SSD (Percentage Used), TBW, температура (brew install smartmontools)
```

## 🟡 29. Производительность и трассировка: DTrace, fs_usage, powermetrics

### Метод USE на macOS

Для каждого ресурса проверяем **U**tilization (загрузку), **S**aturation (очередь / нехватку), **E**rrors (ошибки):

| Ресурс | Загрузка (Utilization) | Насыщение (Saturation) | Ошибки (Errors) |
|---|---|---|---|
| **CPU** | `top -o cpu`, `sudo powermetrics` | `uptime` (load average), `sysctl vm.loadavg` | Термотроттлинг в `powermetrics --samplers thermal` |
| **Память** | `memory_pressure`, `vm_stat` | Сжатие (`Pages occupied by compressor`) и `Swapins`/`Swapouts` в `vm_stat 1` | `jetsam` / `low swap` в `log show` |
| **Диск** | `iostat -Id 1`, `sudo fs_usage` | Высокое время отклика в `fs_usage` | `smartctl -a disk0`, `diskutil verifyVolume /` |
| **Сеть** | `nettop -P`, `netstat -ib` | Потери и ретрансмиты в `netstat -s -p tcp` | Ошибки интерфейса `Ierrs`/`Oerrs` в `netstat -i` |

### Первые 60 секунд на тормозящем Mac

```bash
uptime                                                   # load average и сколько дней Mac не перезагружался
ps aux -r | head -10                                     # топ процессов по CPU прямо сейчас
ps aux -m | head -10                                     # топ процессов по памяти
memory_pressure                                          # хватает ли памяти (free percentage)
vm_stat 1 5                                              # идут ли прямо сейчас pageouts (выгрузка в swap)
iostat -w 1 -c 5                                         # скорость чтения/записи на SSD и загрузка CPU
pmset -g thermlog                                        # нет ли перегрева и троттлинга процессора
```

### Заглянуть внутрь процесса (нативные утилиты macOS) 💡

В macOS вместо `/proc/PID/*` есть мощнейший набор встроенных инструментов анализа процесса:

| Команда | Что показывает |
|---|---|
| `footprint PID` | 💡 Точный отчёт о физическом потреблении памяти процессом (Dirty, Clean, Compressed) |
| `vmmap --summary PID` | Подробная карта регионов виртуальной памяти процесса (аналог `pmap`) |
| `heap PID` | Анализ объектов в куче (heap) процесса по классам (C++ / Objective-C / Swift) |
| `leaks PID` | 💡 Найти утечки памяти (memory leaks) в живом процессе без перезапуска! |
| `sample PID 5` | 💡 Снимать стек вызовов процесса 5 секунд (1000 раз/сек) и показать, в каких функциях он проводит время! |
| `lsof -p PID` | Все открытые процессом файлы, библиотеки и сетевые сокеты |

### Системная трассировка: `fs_usage`, `sc_usage`, `dtruss` (DTrace)

Вместо `strace` и `iotop` в macOS встроены инструменты реального времени на базе ядра и **DTrace**:

```bash
# Кто прямо сейчас читает и пишет файлы на диске (лучшая замена iotop + inotify):
sudo fs_usage -w -f filesys                              # все файловые операции в реальном времени со временем выполнения
sudo fs_usage -w -f filesys Safari                       # файловая активность только процесса Safari
sudo fs_usage -w -f network                              # сетевые системные вызовы всех процессов

# Статистика системных вызовов и страничных ошибок (page faults) конкретного процесса каждую секунду:
sudo sc_usage PID

# Трассировка системных вызовов (аналог strace на базе DTrace; для системных бинарников требует отключения SIP):
sudo dtruss -p PID                                       # системные вызовы запущенного процесса
sudo dtruss -c ./myapp                                   # сводная таблица вызовов программы
sudo opensnoop -n myapp                                  # какие файлы открывает процесс
sudo execsnoop                                           # ловить все запускаемые в системе процессы (даже живущие 1 мс)
```

> 💡 Если установлен Xcode, для глубокого профилирования CPU, памяти и энергопотребления из терминала используй `xcrun xctrace record --template 'Time Profiler' --attach PID --time-limit 10s`.

## 🟡 30. Launchd для профи

### Домены `launchd` (современный интерфейс `launchctl`)

В современном `launchctl` к каждой службе обращаются по пути **`домен/имя-службы`**:

| Домен | Пример цели (`service-target`) | Описание |
|---|---|---|
| `system` | `system/com.openssh.sshd` | Системные демоны (работают от `root` с момента загрузки) |
| `user/<uid>` | `user/501/com.user.agent` | Фоновые агенты пользователя (доступны даже без GUI-сессии) |
| `gui/<uid>` | `gui/501/com.user.app` | Агенты графической сессии пользователя (имеют доступ к экрану, Aqua и буферу обмена) |
| `pid/<pid>` | `pid/1234/...` | XPC-сервисы внутри конкретного процесса |

### Продвинутые команды `launchctl`

| Команда | Что делает |
|---|---|
| `launchctl print gui/$(id -u)` | Показать все службы, переменные окружения и порты графической сессии |
| `launchctl print system/com.openssh.sshd` | Полная информация о службе: PID, путь к `.plist`, сокеты, счётчик перезапусков |
| `launchctl blame system/com.apple.apsd` | 💡 Узнать, **почему** и по чьему триггеру была запущена служба! |
| `launchctl kickstart -kp gui/$(id -u)/com.user.myapp` | Убить текущий процесс службы (`-k`), запустить заново и вывести новый PID (`-p`) |
| `launchctl disable gui/$(id -u)/com.user.myapp` | Запретить запуск службы (сохраняется в базе overrides) |
| `launchctl enable gui/$(id -u)/com.user.myapp` | Снова разрешить запуск службы |
| `sfltool dumpbtm` | 💡 Показать полный список всех фоновых объектов автозапуска (**Background Task Management** в macOS Ventura+) |

### Боевой `.plist`: автоперезапуск, лимиты, расписание и слежение за папкой

В `launchd` один `.plist` заменяет и `.service`, и `.timer`, и `.path`, и `.socket` из `systemd`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.alex.worker</string>

    <key>ProgramArguments</key>
    <array>
        <string>/Users/alex/bin/worker.sh</string>
    </array>

    <key>WorkingDirectory</key>
    <string>/Users/alex</string>

    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
    </dict>

    <!-- Перезапускать только если процесс завершился с ошибкой (ненулевой код выхода) -->
    <key>KeepAlive</key>
    <dict>
        <key>SuccessfulExit</key>
        <false/>
    </dict>

    <!-- Защита от слишком частых перезапусков (секунды) -->
    <key>ThrottleInterval</key>
    <integer>10</integer>

    <!-- Энергоэффективность: выполнять на E-ядрах (Background / Standard / Adaptive / Interactive) -->
    <key>ProcessType</key>
    <string>Background</string>

    <!-- Лимиты ресурсов (например, максимум открытых файлов) -->
    <key>SoftResourceLimits</key>
    <dict>
        <key>NumberOfFiles</key>
        <integer>65536</integer>
    </dict>

    <!-- ИЛИ запуск по расписанию (аналог cron / systemd .timer: каждый день в 03:30) -->
    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>3</integer>
        <key>Minute</key>
        <integer>30</integer>
    </dict>

    <!-- ИЛИ автоматический запуск при любом изменении файла/папки! -->
    <key>WatchPaths</key>
    <array>
        <string>/Users/alex/Downloads</string>
    </array>

    <key>StandardOutPath</key>
    <string>/tmp/worker.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/worker.err</string>
</dict>
</plist>
```

> 🔴 Для системных демонов в `/Library/LaunchDaemons/*.plist` права на файл **обязательно** должны быть `644`, а владелец — `root:wheel` (`sudo chown root:wheel /Library/LaunchDaemons/my.plist && sudo chmod 644 ...`), иначе `launchd` откажется его загружать из соображений безопасности!

## 🟡 31. Ядро XNU: sysctl, nvram, System Extensions и kexts, Mach

### `sysctl` — параметры ядра XNU на лету

```bash
sysctl -a                                            # все доступные параметры ядра (тысячи строк)
sysctl -a | grep machdep.cpu                         # характеристики процессора
sysctl kern.ostype kern.osrelease kern.version       # информация о сборке XNU
sysctl net.inet.ip.forwarding                        # прочитать один параметр
sudo sysctl -w net.inet.ip.forwarding=1              # включить IP forwarding (маршрутизацию) до перезагрузки
```

| Важный параметр `sysctl` в macOS | Что показывает / зачем менять |
|---|---|
| `hw.memsize` / `hw.ncpu` | Физический объём RAM в байтах / число логических ядер |
| `kern.maxfiles` / `kern.maxfilesperproc` | Лимит открытых файлов во всей системе и на один процесс |
| `kern.bootargs` | Аргументы, с которыми было загружено ядро XNU |
| `vm.swapusage` | Сводка по использованию swap (total, used, free, encrypted) |
| `net.inet.ip.forwarding` | `1` — разрешить пересылку пакетов между интерфейсами (для VPN-сервера / роутинга) |
| `net.inet.tcp.mssdflt` / `net.inet.tcp.win_scale_factor` | Тонкая настройка TCP-стека |
| `security.mac.amfi.*` | Статус Apple Mobile File Integrity (проверка подписей кода в ядре) |

### NVRAM — энергонезависимая память загрузчика

```bash
nvram -p                                             # показать все переменные NVRAM
sudo nvram boot-args="-v"                            # включить Verbose Boot (текстовый лог при загрузке Mac)
sudo nvram -d boot-args                              # удалить переменную (вернуть обычную загрузку с яблоком)
sudo nvram StartupMute=%01                           # отключить звук «гонга» при включении Mac (%00 — включить)
```

### Расширения системы (`System Extensions`) и модули ядра (`kexts`) 💡

В современных версиях macOS Apple заменила старые ядерные драйверы (**Kernel Extensions, `.kext`**), ошибка в которых могла вызвать Kernel Panic всей системы, на безопасные пользовательские **System Extensions** (**DriverKit**, **NetworkExtension** для VPN и файрволов, **EndpointSecurity** для антивирусов и EDR):

| Команда | Что делает |
|---|---|
| `systemextensionsctl list` | 💡 Список всех установленных и активных `System Extensions` (VPN, LuLu, Docker, антивирусы) |

| `ioreg -l -w 0 \| less` | Полное дерево устройств и драйверов **I/O Kit** в ядре XNU |

## 🟡 32. Безопасность macOS: SIP, Gatekeeper, TCC, Keychain, Sandboxing

Безопасность macOS строится на нескольких независимых эшелонах защиты:

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. Secure Boot & SSV  — загрузка только подписанной ОС, неизменяемый /  │
│ 2. SIP (csrutil)      — защита системных папок и процессов даже от root │
│ 3. Gatekeeper & Notarization — проверка подписи скачанных программ      │
│ 4. XProtect & MRT     — встроенные сигнатуры и поведенческий антивирус  │
│ 5. App Sandbox & TCC  — изоляция приложений и запрос доступа к Камере/ФС│
└─────────────────────────────────────────────────────────────────────────┘
```

### 1. SIP (System Integrity Protection — «Rootless»)

SIP запрещает изменять `/System`, `/usr`, `/bin`, `/sbin` и подключаться отладчиком к системным процессам даже пользователю `root`!

```bash
csrutil status        # Проверить статус SIP: enabled (должен быть включён!) или disabled
```
*(Изменить статус SIP можно только загрузившись в **macOS Recovery**).*

### 2. Gatekeeper, цифровая подпись (`codesign`) и карантин

Когда браузер скачивает программу из интернета, он вешает на неё атрибут `com.apple.quarantine`. При первом запуске **Gatekeeper** проверяет подпись разработчика и нотаризацию Apple (`Notarization`):

| Команда | Что делает |
|---|---|
| `spctl --status` | Статус Gatekeeper (`assessments enabled`) |
| `spctl -a -vvv -t install /Applications/App.app` | Проверить, доверяет ли Gatekeeper приложению и кем оно нотаризовано |
| `codesign -dv --verbose=4 /Applications/App.app` | Показать сертификат разработчика (`Authority`, `TeamIdentifier`) |
| `codesign --verify --deep --strict /Applications/App.app` | Проверить целостность цифровой подписи (не изменён ли бинарник) |
| `codesign -d --entitlements :- /Applications/App.app` | 💡 Посмотреть **Entitlements** (какие особые права запрошены у системы) |
| `sudo xattr -rd com.apple.quarantine /Applications/App.app` | 💡 Разрешить запуск скачанного open-source приложения без цифровой подписи |

### 3. TCC (Transparency, Consent, and Control) — разрешения приложений

TCC отвечает за всплывающие окна «Приложение просит доступ к папке Документы / Камере / Микрофону / Записи экрана»:

```bash
# Сбросить все выданные или запрещённые разрешения TCC для конкретного приложения (по его Bundle ID):
tccutil reset All com.visualstudio.code
tccutil reset Camera                                     # сбросить доступ к камере для всех программ
tccutil reset Microphone                                 # сбросить доступ к микрофону
tccutil reset SystemPolicyAllFiles com.googlecode.iterm2 # сбросить настройки Полного доступа к диску для iTerm2

# Узнать Bundle ID любого приложения .app:
osascript -e 'id of app "Safari"'                        # → com.apple.Safari
mdls -name kMDItemCFBundleIdentifier -r /Applications/Safari.app
```

### 4. Связка ключей macOS Keychain (`security`) — безопасное хранение секретов 💡

Никогда не храни пароли и API-токены открытым текстом в `.zshrc` или скриптах! Используй встроенную зашифрованную связку ключей **macOS Keychain** через утилиту `security`:

```bash
# Сохранить секретный API-токен в Keychain:
security add-generic-password -a "$USER" -s "my_openai_api_key" -w "sk-secret-12345"

# Прочитать секрет обратно в переменную внутри скрипта (не светя его в истории команд и коде!):
export OPENAI_API_KEY=$(security find-generic-password -a "$USER" -s "my_openai_api_key" -w)

# Посмотреть все доверенные корневые сертификаты в системе:
security find-certificate -a /System/Library/Keychains/SystemRootCertificates.keychain | grep "labl"
```

### 5. Песочница (`sandbox-exec`) — запустить недоверенный скрипт в изоляции

```bash
# Запустить команду с полным запретом доступа в интернет (no-network):
sandbox-exec -p '(version 1)(allow default)(deny network*)' ./untrusted_script.sh

# Запретить программе писать файлы куда-либо, кроме /tmp:
sandbox-exec -p '(version 1)(allow default)(deny file-write*)(allow file-write* (subpath "/private/tmp"))' ./app
```

### Быстрый аудит безопасности своего Mac

```bash
csrutil status                                        # включён ли SIP (должен быть enabled)
spctl --status                                        # включён ли Gatekeeper (assessments enabled)
fdesetup status                                       # включено ли шифрование диска FileVault (FileVault is On)
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate   # статус файрвола
sudo lsof -iTCP -sTCP:LISTEN -n -P                    # какие порты открыты и ждут подключений
ls -la /Library/LaunchDaemons /Library/LaunchAgents ~/Library/LaunchAgents   # что прописано в автозагрузке
systemextensionsctl list                              # какие системные расширения активны
```

## 🟡 33. Контейнеры и ВМ на macOS: OrbStack, Colima, Docker, Tart

### Как работают контейнеры на macOS

Так как контейнеры Linux (`Docker`, `Podman`) используют функции ядра **Linux** (`namespaces`, `cgroups`), а в macOS работает ядро **XNU**, любой контейнерный рантайм на Mac прозрачно запускает лёгкую виртуальную машину Linux поверх нативного системного гипервизора **`Virtualization.framework`**.

```
Команда docker run на Mac
   └──▶ Клиент Docker CLI (/opt/homebrew/bin/docker)
         └──▶ UNIX-сокет пробрасывается в лёгкую Linux-ВМ (Virtualization.framework)
               ├── Нативно выполняет arm64-контейнеры на полной скорости Apple Silicon
               └── Через Rosetta 2 сверхбыстро запускает x86_64 (amd64) контейнеры!
```

### Что выбрать для запуска контейнеров на Mac

| Инструмент | Как установить | Особенности |
|---|---|---|
| **OrbStack** 💡 | `brew install --cask orbstack` | Самый быстрый и лёгкий рантайм для macOS: стартует за 2 секунды, почти не ест RAM и батарею, даёт доменные имена `*.orb.local` для контейнеров и полные Linux-машины |
| **Colima** | `brew install colima docker` | Полностью бесплатный open-source рантайм на базе Lima (`colima start --arch aarch64 --vm-type=vz --vz-rosetta`) |
| **Docker Desktop** | `brew install --cask docker` | Официальный GUI от Docker (требует платную подписку для крупных компаний) |
| **Podman** | `brew install podman` | Бесплатная замена Docker без демона (`podman machine init && podman machine start`) |
| **Tart** 💡 | `brew install cirruslabs/cli/tart` | Нативная виртуализация **macOS** и Linux на Apple Silicon (идеально для локальных macOS-ВМ и CI/CD) |

### Docker / Podman — шпаргалка

| Команда | Что делает |
|---|---|
| `docker run -d --name web -p 8080:80 nginx` | Запустить контейнер в фоне с пробросом порта |
| `docker run --rm -it ubuntu bash` | Запустить временный интерактивный контейнер Ubuntu и удалить после выхода |
| `docker run --platform linux/amd64 --rm -it ubuntu uname -m` | 💡 Принудительно запустить `x86_64` образ на Apple Silicon (через Rosetta 2) |
| `docker ps -a` | Список всех контейнеров |
| `docker logs -f --tail 100 web` | Следить за логами контейнера |
| `docker exec -it web sh` | Зайти внутрь работающего контейнера |
| `docker stats` | Потребление CPU и RAM контейнерами в реальном времени |
| `docker build -t myapp:1.0 .` | Собрать образ для текущей архитектуры |
| `docker buildx build --platform linux/amd64,linux/arm64 -t user/app:1.0 --push .` | 💡 Собрать мультиархитектурный образ (и для Mac M1–M4, и для серверов x86_64!) |
| `docker system df` / `docker system prune -a` | Сколько места занимает Docker / 🔴 удалить все неиспользуемые образы и кэш |
| `docker compose up -d` / `docker compose down` | Поднять / остановить проект из `compose.yaml` |

## 🔴 34. Восстановление системы (RecoveryOS, DFU, сброс пароля)

### Как войти в среду восстановления (macOS Recovery)

- **Mac на Apple Silicon (M1 / M2 / M3 / M4):** полностью выключи Mac → нажми и **удерживай кнопку питания (Touch ID)**, пока на экране не появится надпись *«Загрузка параметров запуска»* → выбери **Параметры (Options)** → в верхнем меню *Утилиты → Терминал*.
- **Mac на Intel:** включи Mac и сразу зажми **`Cmd + R`** до появления логотипа Apple.

### Сбросить забытый пароль входа в macOS

1. Загрузись в **macOS Recovery** и открой **Терминал** (*Утилиты → Терминал*).
2. Введи одну команду:
   ```bash
   resetpassword
   ```
3. Откроется графический мастер сброса пароля (если включён FileVault, потребуется пароль Apple ID или ключ восстановления FileVault).

### Частые аварии на Mac и быстрые решения

| Симптом | Что делать |
|---|---|
| Приложение пишет **«Повреждено и не может быть открыто»** или «Разработчик не проверен» | Сними атрибут карантина: `sudo xattr -rd com.apple.quarantine /Applications/App.app` |
| Завис **Finder**, верхнее меню или **Dock** | `killall Finder`, `killall SystemUIServer`, `killall Dock` |
| Графический интерфейс завис целиком | Нажми `Cmd + Option + Esc` (Принудительное завершение) или зайди по SSH и выполни `sudo killall -HUP WindowServer` (выбросит на экран входа) |
| «Системные данные» (System Data) заняли весь SSD | Удали старые локальные снапшоты Time Machine (`sudo tmutil thinlocalsnapshots / 30000000000 4`), очисти `~/Library/Caches` и `~/Library/Developer/Xcode/DerivedData` |
| Ошибка диска APFS / не монтируется внешний том | В Recovery (или для внешнего диска): `diskutil verifyDisk diskX` и `diskutil repairVolume diskXsY` |
| Случайно сломал `/etc/sudoers` | Загрузись в RecoveryOS → открой Терминал → исправь `/Volumes/Macintosh\ HD/private/etc/sudoers` |
| Сброс **NVRAM** и **SMC** | На **Apple Silicon** достаточно полностью выключить Mac, подождать 30 секунд и включить (SMC интегрирован в чип M-серии, а NVRAM сбрасывается автоматически при сбое загрузки) |
| Mac вообще не включается после сбоя обновления прошивки | Восстановление в режиме **DFU** через второй Mac с кабелем USB-C и встроенным в Finder / Apple Configurator режимом *Revive / Restore* |

> 💡 Лучшее восстановление — бэкап **Time Machine** на внешний SSD или NAS (по SMB) + правило **3-2-1**: 3 копии данных, 2 разных носителя, 1 копия — в облаке или вне дома.

## 🎯 35. Вопросы с собеседований

<details>
<summary><b>1. Что происходит в macOS, когда вводишь <code>ls</code> и жмёшь Enter?</b></summary>

Оболочка **Zsh** читает строку, раскрывает алиасы, переменные и маски, ищет `ls` среди функций, встроенных команд и по каталогам `$PATH` (`/bin/ls`). Затем вызывает `posix_spawn()` (или `fork()` + `execve()`), загрузчик динамических библиотек **`dyld`** подключает `/usr/lib/libSystem.B.dylib` (из общего кэша `dyld shared cache`), процесс проходит проверку подписи ядром (**AMFI**) и профилей **TCC** (если читается защищённая папка вроде `~/Desktop`), вызывает системный вызов `getdirentries64()` к VFS/APFS и выводит результат через `write()` в `stdout` (псевдотерминал `/dev/ttys000`).
</details>

<details>
<summary><b>2. Чем гибридное ядро XNU в macOS отличается от монолитного ядра Linux?</b></summary>

Ядро **XNU** («X is Not Unix») состоит из трёх частей в едином адресном пространстве ядра: 1) микроядро **Mach** (отвечает за низкоуровневое планирование потоков, виртуальную память и межпроцессное взаимодействие через порты `Mach ports` / IPC), 2) слой **BSD** (на базе FreeBSD: процессы с PID, POSIX-вызовы, пользователи/группы, виртуальная файловая система VFS и сетевой стек) и 3) **I/O Kit** (фреймворк драйверов устройств на подмножестве C++). Такое сочетание даёт модульность микроядра без потерь производительности на переключение контекста.
</details>

<details>
<summary><b>3. Почему в macOS даже пользователь <code>root</code> не может создать папку в корне <code>/</code> или изменить <code>/usr/bin</code>?</b></summary>

По двум причинам: 1) **SIP (System Integrity Protection)** на уровне ядра блокирует модификацию системных каталогов (`/System`, `/usr`, `/bin`, `/sbin`) для любых процессов, включая `root` (UID 0). 2) Начиная с macOS Big Sur, корневой том `/` является **Signed System Volume (SSV)** — он криптографически подписан Apple и монтируется с неизменяемого снапшота APFS **строго в режиме чтения (read-only)**. Все изменяемые данные живут на томе `/System/Volumes/Data` и пробрасываются в корень через **firmlinks** (а свои корневые точки монтирования можно объявлять через `/etc/synthetic.conf`).
</details>

<details>
<summary><b>4. Почему Finder показывает 100 ГБ свободно, а <code>df -h</code> в терминале — всего 20 ГБ?</b></summary>

В macOS есть концепция **очищаемого места (Purgeable Space)**: локальные снапшоты Time Machine (`com.apple.TimeMachine.*.local`), кэши iCloud Drive и временные системные кэши физически занимают блоки на APFS (поэтому честная UNIX-утилита `df -h` считает их занятыми), но macOS помечает их как «очищаемые» и автоматически удалит по первому требованию программы, которой понадобится место (поэтому Finder оптимистично прибавляет их к доступному месту). Освободить это место вручную можно командой `sudo tmutil thinlocalsnapshots / 50000000000 4`.
</details>

<details>
<summary><b>5. В чём разница между <code>LaunchDaemons</code> и <code>LaunchAgents</code> в <code>launchd</code>?</b></summary>

- **`LaunchDaemons`** (`/Library/LaunchDaemons`, `/System/Library/LaunchDaemons`) запускаются в системном домене (`system/`) при загрузке самого Mac **до входа какого-либо пользователя**, работают от имени `root` (если не указан `UserName`) и не имеют доступа к графическому интерфейсу (`WindowServer`) или буферу обмена.
- **`LaunchAgents`** (`~/Library/LaunchAgents`, `/Library/LaunchAgents`) запускаются в графическом домене пользователя (`gui/<uid>/`) **только когда пользователь входит в систему**, работают от его имени и имеют доступ к GUI, Связке ключей пользователя и его сессии.
</details>

<details>
<summary><b>6. Как на Mac с чипом Apple Silicon (ARM64) работают программы, написанные под процессоры Intel (x86_64)?</b></summary>

Двумя способами: 1) **Universal 2 Binary (Fat Binary)** — один исполняемый файл Mach-O содержит сразу две скомпилированные ветки машинного кода (`arm64` и `x86_64`); проверить можно командой `lipo -info /Applications/App.app/Contents/MacOS/App` или `file`. 2) Если бинарник содержит только код `x86_64`, прозрачно включается транслятор **Rosetta 2**, который переводит инструкции x86_64 в ARM64 (в основном заранее при первом запуске — Ahead-of-Time, плюс аппаратная поддержка модели памяти TSO в чипах Apple M-серии). Установить Rosetta 2 из терминала: `softwareupdate --install-rosetta --agree-to-license`.
</details>

<details>
<summary><b>7. Почему команда <code>sudo echo "127.0.0.1 test.local" >> /etc/hosts</code> выдаёт Permission denied?</b></summary>

Потому что перенаправление `>>` выполняет **текущая оболочка** (под твоим обычным пользователем) ещё **до** запуска `sudo`! Правильный способ — передать поток в программу, запущенную через `sudo`:
`echo "127.0.0.1 test.local" | sudo tee -a /etc/hosts`.
</details>

<details>
<summary><b>8. В чём отличие <code>kill -15</code> (SIGTERM) от <code>kill -9</code> (SIGKILL)?</b></summary>

`SIGTERM` (15, сигнал по умолчанию) — вежливая просьба завершиться: процесс может перехватить сигнал, сохранить состояние, закрыть БД и удалить lock-файлы. `SIGKILL` (9) обрабатывается напрямую ядром XNU: процесс уничтожается мгновенно без возможности выполнить код очистки. Единственный случай, когда `kill -9` не сработает, — если процесс находится в состоянии `U` (Uninterruptible wait в ядре, например ждёт зависшую сетевую шару NFS/SMB) или `Z` (зомби, который уже мёртв).
</details>

<details>
<summary><b>9. Почему скрипт на Mac выдаёт <code>Operation not permitted</code> при чтении <code>~/Desktop</code>, даже если запущен через <code>sudo</code>?</b></summary>

В macOS поверх стандартных прав UNIX и `root` работает подсистема конфиденциальности **TCC (Transparency, Consent, and Control)**. Папки `~/Desktop`, `~/Documents`, `~/Downloads`, а также базы Почты, Сообщений и Safari защищены TCC: если у родительского приложения (например, `Terminal.app`, `iTerm2` или `cron`) нет выданного пользователем разрешения в *Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску (Full Disk Access)*, ядро заблокирует доступ даже для `root`!
</details>

<details>
<summary><b>10. Как в macOS устроена работа с памятью и почему нет фиксированного раздела swap?</b></summary>

Ядро XNU активно использует сжатие памяти (**Compressor**): когда оперативной памяти не хватает, неактивные страницы сначала сжимаются прямо в RAM в несколько раз. Если давление на память (**Memory Pressure**) продолжает расти, демон `dynamic_pager` автоматически создаёт зашифрованные файлы подкачки `/System/Volumes/VM/swapfile0`, `swapfile1`… на томе `VM` внутри контейнера APFS, а когда нагрузка спадает — освобождает их.
</details>

<details>
<summary><b>11. Где в macOS хранятся настройки системы и приложений и как менять их из скриптов?</b></summary>

В файлах списков свойств **Property Lists (`.plist`)** в папках `~/Library/Preferences/` и `/Library/Preferences/` (в бинарном или XML формате). Напрямую править файлы текстовым редактором нельзя, так как их кэширует системный демон **`cfprefsd`**. Для чтения и изменения настроек используется команда **`defaults`** (например: `defaults write com.apple.finder AppleShowAllFiles -bool true && killall Finder`).
</details>

## 🩺 36. Диагностика: что делать, если…

<details>
<summary><b>💾 Закончилось место на диске (или «Системные данные» весят 100+ ГБ)</b></summary>

```bash
df -h /System/Volumes/Data                                  # сколько реально свободно на томе данных
du -hd 1 ~ 2>/dev/null | sort -hr | head -15                # какие папки в домашней директории самые тяжёлые
du -hd 1 ~/Library/Caches 2>/dev/null | sort -hr | head -10 # какие приложения раздули кэш

# 1. Проверить и почистить локальные снапшоты Time Machine:
tmutil listlocalsnapshots /
sudo tmutil thinlocalsnapshots / 30000000000 4              # освободить до 30 ГБ

# 2. Очистить кэш Homebrew:
brew cleanup -s && rm -rf "$(brew --cache)"

# 3. Если ты разработчик: проверить гигантские папки Xcode и Docker:
du -sh ~/Library/Developer/Xcode/DerivedData ~/Library/Developer/CoreSimulator/Devices 2>/dev/null
xcrun simctl delete unavailable                             # удалить старые симуляторы iOS
docker system df                                            # проверить размер образов Docker

# 4. Найти удалённые файлы, которые всё ещё держит открытыми какой-то процесс:
sudo lsof -nP +L1
```
</details>

<details>
<summary><b>🔥 Mac тормозит, шумит вентиляторами или быстро разряжается</b></summary>

```bash
uptime                                                      # load average против sysctl -n hw.ncpu
ps aux -r | head -10                                        # кто прямо сейчас жрёт CPU
```

## ⚠️ 37. Опасные команды 🔴

Никогда не запускай их, не понимая последствий, — особенно если их прислали в чате или статье без объяснений.

| Команда | Что произойдёт в macOS |
|---|---|
| `rm -rf ~` или `rm -rf /*` | Удалит все твои личные файлы и данные (SIP спасёт только саму ОС, но не твои документы!) |
| `rm -rf $DIR/` при пустой `$DIR` | Превратится в `rm -rf /` — всегда пиши `"${DIR:?}/"` |
| `sudo diskutil eraseDisk ... disk0` | Полностью сотрёт системный SSD вместе со всеми томами |
| `sudo dd if=/dev/zero of=/dev/rdisk0` | Мгновенно уничтожит таблицу разделов и данные на диске |
| `sudo chmod -R 777 /Applications` или `/Library` | Сломает проверку подписей и права `LaunchDaemons` — службы перестанут запускаться |
| `csrutil disable` (на постоянной основе) | Отключит SIP и сделает Mac уязвимым для малвари и руткитов |
| `:(){ :\|:& };:` | Fork-бомба — исчерпает лимит процессов и намертво повесит систему |
| `curl URL \| sudo sh` | Запустит неизвестный скрипт из интернета с правами `root` |
| `security delete-keychain login.keychain-db` | Удалит связку ключей со всеми сохранёнными паролями и сертификатами |

### Сценарий 4. Разбор логов веб-сервера: кто, что и с какой ошибкой

Формат `combined`: `$1` — IP, `$4` — время, `$7` — URL, `$9` — HTTP-код ответа, `$10` — размер в байтах.

```bash

awk '$9 >= 500 {print $7}' "$LOG" | sort | uniq -c | sort -rn | head   # какие URL чаще всего отдают 5xx
awk '{print $7}' "$LOG" | sort | uniq -c | sort -rn | head          # самые популярные страницы
awk -F'"' '{print $6}' "$LOG" | sort | uniq -c | sort -rn | head    # топ User-Agent (боты и браузеры)
awk '{s += $10} END {printf "%.1f MB\n", s/1048576}' "$LOG"         # суммарный отданный трафик
tail -f "$LOG" | grep --line-buffered '" 5[0-9][0-9] '              # ловить ошибки 5xx в реальном времени
```

<details>
<summary><b>21. Напиши скрипт check_disk.sh для macOS: предупреждение, если том /System/Volumes/Data заполнен больше чем на N% (по умолчанию 80), и код выхода 1</b></summary>

```bash
#!/usr/bin/env bash
set -euo pipefail

limit=${1:-80}
use=$(df -P /System/Volumes/Data | awk 'NR==2 {gsub(/%/,"",$5); print $5}')

if (( use > limit )); then
  echo "⚠️  Диск заполнен на ${use}% (порог: ${limit}%)"
  exit 1
else
  echo "✅ Свободно достаточно места (занято ${use}%)"
  exit 0
fi
```

```bash
chmod +x check_disk.sh
./check_disk.sh 10; echo "код выхода: $?"
```

## 📘 Глоссарий

| Термин | Коротко |
|---|---|
| **XNU** | Гибридное ядро macOS и iOS, объединяющее микроядро Mach, слой FreeBSD и фреймворк драйверов I/O Kit |
| **Darwin** | Открытая UNIX-основа macOS (ядро XNU + утилиты BSD + `launchd`) |
| **Mach** | Нижняя часть ядра XNU: управляет планировщиком потоков, виртуальной памятью и IPC (`Mach ports`) |
| **Aqua / WindowServer** | Графический интерфейс macOS и системный процесс, отрисовывающий все окна на экране |
| **Zsh** | Стандартная командная оболочка в macOS (по умолчанию с macOS Catalina) |
| **APFS** | Apple File System — современная файловая система macOS с Copy-on-Write, общим пулом места контейнера, клонами и снапшотами |
| **SSV (Signed System Volume)** | Неизменяемый системный том `/`, смонтированный только для чтения и заверенный криптографической подписью Apple |
| **Firmlink** | Двунаправленная связка между системным read-only томом `/` и изменяемым томом `/System/Volumes/Data` |
| **Bundle (`.app`)** | Папка со специальной структурой (`Contents/MacOS`, `Info.plist`), которая выглядит для пользователя как один файл программы |
| **Plist (Property List)** | Файл настроек и метаданных macOS (в XML или бинарном формате), читается через `plutil` и `defaults` |
| **`launchd`** | Главный системный процесс macOS (PID 1), управляющий демонами (`LaunchDaemons`) и агентами (`LaunchAgents`), аналог `systemd` |
| **Open Directory** | Служба каталогов macOS (`opendirectoryd`), хранящая пользователей и группы; управляется утилитами `dscl` и `sysadminctl` |
| **`xattr`** | Расширенные атрибуты файла (например, метка карантина `com.apple.quarantine` или теги Finder) |
| **SIP (System Integrity Protection)** | Защита системных файлов и процессов на уровне ядра даже от суперпользователя `root` (`csrutil`) |
| **Gatekeeper & Notarization** | Система проверки цифровой подписи разработчика и облачной проверки Apple на отсутствие вредоносного кода перед первым запуском программы |
| **TCC** | Transparency, Consent, and Control — подсистема разрешений на доступ приложений к Камере, Микрофону, Экрану и папкам пользователя |
| **Keychain** | Зашифрованное системное хранилище паролей, ключей и сертификатов macOS (консольная утилита `security`) |
| **Secure Enclave** | Изолированный сопроцессор безопасности в чипах Apple, хранящий криптографические ключи и данные Touch ID |
| **System Extension / DriverKit** | Современная замена модулей ядра (`.kext`), позволяющая драйверам, VPN и антивирусам работать в пространстве пользователя без риска уронить ядро |
| **Unified Logging** | Централизованная система логирования macOS и iOS, управляемая утилитой `log` и приложением `Console.app` |
| **Universal Binary (Fat Binary)** | Исполняемый файл Mach-O, содержащий нативный код сразу для двух архитектур: `arm64` (Apple Silicon) и `x86_64` (Intel) |
| **Rosetta 2** | Быстрый транслятор в macOS на Apple Silicon, позволяющий запускать приложения и контейнеры, собранные под процессоры Intel (`x86_64`) |
| **Homebrew (`brew`)** | Главный менеджер пакетов (Formulae) и приложений (Casks) для macOS |
